A.2: Recover Homographies

A homography H is a matrix that maps a point (x, y) in image 1 to its matching point (x', y') in image 2:

x' = (a·x + b·y + c) / (g·x + h·y + 1)
y' = (d·x + e·y + f) / (g·x + h·y + 1)

H = [ a  b  c ]
    [ d  e  f ]
    [ g  h  1 ]

The bottom-right entry is fixed to 1, so there are 8 unknowns. Multiplying both sides by the denominator makes each equation linear in the unknowns, so every pair of matching points gives two rows of a linear system:

[ x  y  1  0  0  0  -x·x'  -y·x' ]   [a b c d e f g h]ᵀ  =  [ x' ]
[ 0  0  0  x  y  1  -x·y'  -y·y' ]                          [ y' ]

Four point pairs give exactly 8 equations, but clicks are never perfect, so I clicked about 10 pairs per set. Stacking them gives a 2n × 8 system A·h = b with more equations than unknowns, which I solved with least squares. This finds the H that best fits all the clicks at once. I wrote this in computeH(im1_pts, im2_pts) without any built-in homography functions.

To check each H, I mapped my image 1 points through it and measured how far they landed from the points I clicked in image 2 (the reprojection error).

A.3: Warp the Images

I wrote two warping functions, warpImageNearestNeighbor(im, H) and warpImageBilinear(im, H), using inverse warping:

  1. Map the four corners of the image through H to find the bounding box of the output.
  2. For every pixel (x, y) in that box, map it backwards through H⁻¹ to find where it came from in the original image. Going backwards means every output pixel gets exactly one value, with no holes.
  3. Sample the original image at that spot. That spot is usually between pixels, which is where the two methods differ:
    • Nearest neighbor: round to the closest pixel and copy it.
    • Bilinear: blend the 4 surrounding pixels, weighted by how close each one is.
  4. Output pixels whose source falls outside the original image are marked empty in an alpha mask, so they show up as transparent instead of black.

Rectification

To test the warps, I rectified two rectangular objects that were photographed at an angle. I clicked the 4 corners of each object and computed the H that sends them to the corners of a flat rectangle. The rectangle's width and height are the average lengths of the opposite clicked edges. Warping the whole image with that H makes the object face the camera head on.

The Hallway Doorway

The doorway photo was taken with the camera rolled about 60°, so most of this H is a rotation. The frame's opposite sides also had different lengths in the photo, since the camera was tilted too. The perspective part of H (its bottom row) evens those out, which a plain rotation couldn't do.

Nearest Neighbor vs. Bilinear

At full size the two results look the same. Zoomed in, nearest neighbor gives straight edges a jagged, stair-stepped outline, because each output pixel goes to one whole source pixel. Bilinear keeps the same edges smooth, but it's slightly softer overall since every pixel is an average of four.

Nearest neighbor is faster because it does one lookup per pixel instead of four plus the blending math. On the TV it took 0.05 s vs. 0.16 s for bilinear, and on the doorway 0.11 s vs. 0.22 s. Bilinear looks noticeably better for a fraction of a second more, so I used it for the mosaics.

A.4: Blend the Images into a Mosaic

For each set, image 1 is the reference and stays as it is. Since H maps image 1 to image 2, I warped image 2 into image 1's view with H⁻¹. Both images go onto one shared canvas, big enough to hold both warped bounding boxes, so matching pixels land in the same place.

Just pasting one image over the other gives a hard seam, so I blended them:

  • Weights: every pixel gets a weight equal to its distance to the nearest edge of its own image, scaled so the center is 1 and the edges are near 0. The weight map is warped along with the image. Where the two images overlap, each one counts more where it is further from its own edge.
  • Two-band blending (a two-level Laplacian pyramid): I split each warped image into a low band (a Gaussian blur) and a high band (image − blur). The low bands are averaged with the weights, low = (w1·low1 + w2·low2) / (w1 + w2), so color and brightness fade smoothly across the overlap. For the high band, each pixel comes from whichever image has the larger weight there, so fine details stay sharp instead of showing up twice when the alignment is a few pixels off. The final mosaic is low + high.

Part B: Feature Matching for Autostitching

In Part A I clicked the correspondences by hand. In Part B the program finds them on its own, following the MOPS paper (Brown, Szeliski and Winder): find corners, describe each one with a small patch, match the patches between the two images, and use RANSAC to throw out the bad matches. I used the same three sets of photos as Part A.

B.1: Harris Corner Detection

I used the provided harris.py to score every pixel with the Harris corner strength, det(H) / tr(H), and keep every pixel that is a maximum in its 3×3 neighborhood. There's no strength threshold, so it returns about 55,000 corners per image. Most of them are tiny bumps from noise on flat walls.

Adaptive Non-Maximal Suppression (ANMS)

Keeping only the 500 strongest corners isn't enough, because they clump together in a few high-contrast spots like the ceiling lights. ANMS gives each corner a radius equal to the distance to the nearest corner that is clearly stronger than it:

r_i = min_j |x_i - x_j|   such that   f(x_i) < 0.9 · f(x_j)

I kept the 500 corners with the largest radii. A corner gets a large radius by being the strongest in its area, so the points end up spread over the whole image. To keep it fast, I only ran ANMS on the 5,000 strongest corners.

B.2: Feature Descriptor Extraction

For each corner I took the 40×40 window around it and sampled every 5th pixel to get an 8×8 patch. I blurred the image first (σ = 2) so the sampling doesn't alias, which means a corner that's off by a pixel or two still gives almost the same patch. Then I normalized each patch to mean 0 and standard deviation 1, so a change in brightness or contrast between the photos doesn't matter.

The patches are also rotated to match each corner's orientation (see B.5), since my second photos are all rotated. The cyan line on each box shows that orientation.

B.3: Feature Matching

The error between two descriptors is the sum of squared differences. For each feature in image 1, I found its nearest (1-NN) and second nearest (2-NN) feature in image 2. Following Lowe and the paper, I kept the match only if

e_1NN / e_2NN < 0.5

The 2-NN is almost always a wrong match, so this keeps a match only if it's much better than a wrong one. I picked 0.5 from Figure 6b in the paper, where there are almost no incorrect matches below that ratio.

Many of these matches are still wrong, especially on the repeating wood grain of the table and the ceiling tiles. RANSAC takes care of those next.

B.4: RANSAC for Robust Homography

One bad match is enough to ruin a least squares homography, so I wrote 4-point RANSAC:

  1. Pick 4 random matches and compute the exact H through them.
  2. Count the inliers: matches where H maps the image 1 point within 4 px of its image 2 point.
  3. Repeat 5,000 times and keep the largest set of inliers.
  4. Recompute H with least squares on all of those inliers, using computeH from Part A.

The wrong matches point in random directions, so they rarely agree with each other, while the correct ones all agree on the same H.

B.5: Bells & Whistles: Rotation Invariance

My first version used axis-aligned patches, and it found almost nothing: 1, 11 and 7 matches, and when I checked them against my Part A homographies, none were correct. The problem is that the second photo in every set is rotated, so the same spot gives a different patch.

Following Section 2 of the paper, I gave each corner an orientation from the gradient of the image blurred with σ = 4.5, θ = atan2(∂I/∂y, ∂I/∂x). Then I rotated the 8×8 sampling grid by θ before sampling (with bilinear interpolation), so every patch is lined up with its own gradient no matter how the camera was turned.

To test it, I matched the room photo against a copy of itself rotated by 26°. That gave 10 matches before and 286 after. On the real photos, the correct matches went from 0 to 15, 42 and 21, which was enough for RANSAC to work.
